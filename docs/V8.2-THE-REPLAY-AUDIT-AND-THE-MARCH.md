## 1 · IS THE REPLAY TOTALLY FIXED?

Two passes, because neither one alone would have been enough.

### The dynamic pass: run it twice and diff everything

`dbg-replay3/4.mjs` runs the SAME scripted pass twice through the real replay
path (`startChapter` -> `setChapter` -> `restart` -> `enterWorld`), UNMUTED,
and diffs every audio surface the engine exposes.

```
run 1: film cues (14) [e2film, seawash, ferryhorn, n1pro1, bootsmarch, gates,
                       bootsrun, n1pro1b, n1pro2, s1bed, lockerdoor, n1pro3,
                       n1pro4, bunkcreak]
run 2: film cues (14) [ identical ]

  hotspot-buddy   voice [b1day]        both runs
  hotspot-board   voice [k1board]      both runs
  hotspot-mate    voice [k1three]      both runs
  fall-in         voice [s1fallin, n1fallin]
  lights-out      voice [s1lights, n1lights, b1sleep]
  three-am        voice [n1wake, n1near]
  loops           identical
  music           playing, same gain
```

**Every cue that fires on a first run fires on a replay.** v8.1's `speakReset`
holds.

One trap worth writing down: the FIRST version of this probe reported run 1
missing `ferryhorn`, which looked like a real cold-decode bug. It was the
probe's own race — the baseline was taken after `state` had already become
`cine`, so the film's first three cues had fired between the wait returning
and the read. **Take the baseline before the call, not after the state
changes.** Re-measured that way, the two runs are identical.

### The static pass: read what reset() forgets

The dynamic pass can only test the paths it walks, and it never ran the
fall-in before resetting. Reading the code found two things it could not.

**(a) `packWarm(WARM_WANT)` sat below `enterWorld`'s no-film early return.**
So a chapter entered with no film — the RESUME path, and any chapter that
declares no `intro` — never decoded what its `build()` asked to warm, and its
first press would have been silent exactly as it was before v8.0. Not
reachable by a shipping chapter today (every playable chapter has a film, and
a cold resume's own pack load drains the set when the bytes land), which is
why nothing caught it. Hoisted above the branch: one line, and it removes the
class rather than the instance. Chapters 1-5 warm nothing, so for them it is
a no-op on an empty set. `src/main.js`'s only change this release.

**(b) `reset()` never called `fallOut(false)`.** Measured on the shipped
build:

```
  on the line : buddy 7.40  mate 7.40  crowd 7.40 x6
  after reset : buddy 7.40  mate 7.40  crowd 7.40 x6     <- unchanged
```

`fallOut(true)` moves eight men out to the yellow line and only
`fallOut(false)` brings them back. So replaying during or after the fall-in
began the new morning with an empty bunk and the whole section already formed
up outside. The encik was the one exception and only by accident:
`putSergeant(SGT_DOOR)` happens to move him too. Fixed, and after:

```
  after reset : buddy -3.05  mate 2.55  crowd -3.25/3.25 x6
```

The general shape, added to the v8.1 law: **a value stated in a clock must be
cleared by whatever resets that clock — and so must a POSITION stated by a
phase.** `reset()` is the list of everything a run can move, and the list is
only correct if it is re-read every time something new can move.

## 2 · THE SECTION FALLS IN ON REAL LEGS

v7.4 PLACED the section on the line and said why: *"neither rig carries a walk
take (the file ships an idle and a talk and nothing else)"*. Chad's three new
models end that. Every one carries `Walking` and `Running`, and both measure
**in place** — the Hips travel 0.02 to 0.04 m over the cycle — which is
exactly the shape ch5's tang-ki has walked on since v5.07: play the take,
glide the group.

So on the whistle all ten men go out on foot, and come back the same way.
Recruits RUN at 2.6 m/s; the sergeant and the encik WALK at 1.35 and leave
last, because a sergeant-major does not race his own section.

**A crowd copy could only ever hold the one action it was built with**, which
is what forced v8.1's "they all stand, and that is forced rather than
preferred". `crowdPlay` lifts it: the clips and the built action are kept, so
a crowd can be put on a different take and back — parked frame and all, which
matters because the botak row's stand IS a parked frame of its walk.

### The route, and the four numbers that were each measured

A cast path obeys no collision (v5.03), so the route is laid by hand: out of
the bed row into the gangway lane, east through the balcony opening (z ±1.2),
then across open floor to his place on the line. Nobody crosses the long
table (z 2.55, x ±1.80) or a bed row (x ±4.6), in either direction.

Four defects, each found by measuring rather than by looking, each fixed by
one rule:

| what went wrong | measured | the rule |
|---|---|---|
| one funnel point | all eight men on (7.4, 0) | past the wall the balcony is open floor — cut straight to the spot |
| three shared lanes | two men standing at (−3.25, −0.45) | a lane per man, eleven of them across ±0.98 |
| dispatch order | the man at the back of a bed column ran through the man in front, 0.01 m | **nearest the door goes first** — sort by route length |
| lanes by dispatch order | the two men who share x 3.25 ran at each other's lane, 0.04 m | **deal lanes by where he STANDS** — deeper in −z gets a deeper −z lane, so two paths never cross |

The last one is the invariant that ends it. Closest two men now come: **0.21 m**,
the lane pitch, at the doorway — which is what a doorway is.

Verified over 191 sampled frames of a whole fall-in and return: no contact with
the table or a bed row, every man exactly on his spot, every man exactly back
at his bed.

he opens his mouth reads as a loop rather than a person.
