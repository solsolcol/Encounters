## The shuffle — one loader for three kinds

The v4.8 encik trick — N offstage skeletons running the clip at staggered
phases, every sitter a `detached`-bind clone pointing at one — is now
`seatKind(key)` and runs three times. Two things had to change to make
that honest, and both were waiting to bite:

1. **The bind matrix is folded in.** v4.8 set the clone's `bindMatrix` and
   `bindMatrixInverse` to identity, and its own comment said that was only
   right "for this file". The source draws `ΣB · M · v` where `M` is its
   mesh node's own matrix, so a clone is right only with `bindMatrix = M`,
   `bindMatrixInverse = I`. For the encik `M = I` and nothing changes; for
   any other file it is the difference between sitting in the chair and
   sitting at the armature's origin.
2. **Every skinned mesh is cloned, not the first.** The encik is one mesh.
   sitclap and sitangry are seven each — body, head, hair, eyes — and the
   first probe render of this build was a tent of **floating heads and
   hands with no bodies under them**, one per seat, because the loader
   took `poseMeshes[j]` as one mesh. The numbers had passed: 19 seats,
   zero placeholders visible. Only the picture caught it.

Each kind hides only ITS OWN seats' placeholders on arrival, so whichever
order the three downloads land in, or if one never does, no chair is ever
empty. `crowd`, `userData.head`, `crowdLife` and the sway loop are
untouched; leaktest builds every chapter and still balances.
