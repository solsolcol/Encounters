## Design decisions, with reasons

1. **The chapter file becomes an IIFE.** `build(ctx)` fills closure
   variables; `scenes` read them. Cutscenes and the world they animate
   are the same chapter, so they share a closure instead of a 20-field
   prop bag passed back and forth. Still a plain script — no ESM, which
   file:// and the CSP build both need.
2. **`A(c)` (the cutscene authoring helpers) stays in the ENGINE** and is
   handed to scenes via ctx. It is the cutscene *language*, not chapter
   content; every chapter writes scenes with the same verbs.
3. **The ghost stays engine.** She is the game's, not chapter 1's — which
   is why `ghost` also moves out of ch1's `assets:` list (step C).
4. **`dispose()` must genuinely free.** Geometries, materials, textures,
   render targets. Proven by a harness that builds/disposes 50× and
   watches `renderer.info`, not by reading the code.
5. **No page reload on chapter advance.** `dispose()` → `build()`. A
   reload re-pays GLB parse, shader compile and audio decode.
6. **Persistence does NOT change boot.** Restore-on-boot is a
   player-visible change to a frozen baseline, and with one chapter it is
   meaningless. The mechanism ships; auto-resume is Chad's call later.

## The rule that stops test bloat (D2)

Most harnesses must never load a real chapter. After D2:
- ~13 engine harnesses load `chtest` (a primitive room, no location GLB) —
  fast and decoupled from chapter content.
- per-chapter correctness is ONE data-driven file: keys resolve, deltas
  sane, stage in bounds, assets exist, scenes complete. Mostly no browser.
- exactly two full-integration harnesses (`final`, `hosted`) stay on a
  real chapter, release-tier.

## Not done, deliberately

**E2 — deleting the embedded build (`hellnote.html`).** Kept. It costs
~5.5 s of build time, it is the anywhere/offline fallback, and it is the
only surface `csptest` can test the strict no-blob/no-data CSP on — the
policy that shaped the hand-parsed GLB and audio loaders. Chad's standing
rule is "don't lose anything", and deleting a working fallback to save
5 seconds is the wrong trade. Revisit only if it starts costing real
download or maintenance weight.
