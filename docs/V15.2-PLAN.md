## 1. The skeleton merge — what it is, and why it cannot change a pixel

MEASURED (tools/probes/skins.mjs, v15.1 build): three's GLTFLoader gives every
skinned PRIMITIVE its own Skeleton, even when many share one skin, and
SkeletonUtils.clone gives every cloned mesh its own again. Each Skeleton is
updated (its matrices recomputed) and uploaded as its own float texture every
frame it is drawn.

| model | meshes | skeletons | rows | bones | bones with >1 inverse-bind | exact union |
|---|---|---|---|---|---|---|
| her (ghost.glb) | 46 | 46 | 233 | 28 | 0 | 28 |
| ch3 Mixamo sitter pose clone (×8) | 7 | 7 | 128–131 | 65 | 0 | 65 |
| ch3 standman | 10 | 10 | 660 | 66 | 66 | 660 |
| ch3/ch5 tangki | 3 | 3 | 55 | 36 | 0 | 36 |
| every episode-2 rig | 1 | 1 | — | — | — | nothing to do |

ch3 at the spawn: 28 skeleton updates and 28 bone-texture uploads per drawn
frame.

THE MERGE is exact by construction: one Skeleton whose rows are the distinct
(bone OBJECT, inverse-bind matrix compared bit for bit) pairs, every mesh's
skinIndex remapped onto those rows. A row's matrix is
`bone.matrixWorld × inverseBind`, computed from the SAME two objects as
before, so the texture holds the same float bits at a different address; the
shader fetches by exact integer (texelFetch), and the CPU path
(`applyBoneTransform`, used for bounds and the sizing code) reads
`bones[i]` and `boneInverses[i]` — the same objects. Nothing else in a
SkinnedMesh changes: its bindMatrix, bindMatrixInverse, geometry positions,
weights, material and program are untouched (the program key has only a
`skinning` flag). It aborts, touching nothing, on anything unusual (a
geometry shared by meshes that would need different remaps, an index out of
range, >65535 rows). It runs inside the parse callback, before any draw, so
the replaced skinIndex was never uploaded. `cloneSkinned` re-shares after
SkeletonUtils.clone: cloned meshes whose sources shared one skeleton share one
clone (same bone mapping and the same `boneInverses` array, verified).

`OPT.skelMerge` (`?opt=skelMerge:0` turns it off) is the switch the proof
compares against.

PROOF, before it ships: `__enc.skelLab()` parses a model twice from the same
bytes, merges one, poses both with their own mixers at several times, and
compares every skinned vertex (`getVertexPosition`, Object.is) and a rendered
frame of each at several turns (pixels, exact). Clones and ch3's detached
sitters are checked the same way. Then skins.mjs again for the counts.

## 2. The fonts at home

Today the page asks fonts.googleapis.com for a stylesheet (render- and
script-blocking, in the body), which names files on fonts.gstatic.com. Google
answers DIFFERENT files per browser (48 UAs probed, 8 distinct answers):
MOBILE (all iOS, all Android but Edge), WIN/LINUX (Chrome/Edge on
Windows/Linux/ChromeOS, Linux Firefox, headless), MAC (Safari, Firefox, Edge,
Opera on a Mac, iPad desktop mode), MAC CHROME, WIN FIREFOX; and one-offs for
Windows Opera, Android Edge, and a full-TTF answer for anything unrecognised
(iPod, Yandex).

The design: a snapshot tool fetches Google's CSS for one representative UA
per class, asserts every UA of the class got the SAME CSS, downloads the
files, and writes a class stylesheet pointing at our copies (content-hashed,
immutable). The page picks a class with an inline selector — strict patterns
that match only the UA shapes that were probed and version floors — and
writes that stylesheet; ANYTHING else gets exactly today's Google link. So a
classified browser receives byte-identical font files to what Google sends it
today, and an unclassified one is unchanged. The single-file build keeps the
Google link (untouched; csptest covers it).

PROOF: the tool asserts per-class CSS equality over the probe list and
checks every UA's class against Google's real answer for it; the headless
test browser (WIN/LINUX class) is rendered with the self-hosted fonts and
with Google's, text screens compared pixel for pixel.

## 3. Samsung

To be investigated: item views are drawn by one offscreen WebGL renderer and
copied into 2D canvases; the figure is its own WebGL canvas. Candidates:
Samsung Internet's forced dark mode (it can repaint canvases/images), MSAA
not granted on some GPUs, depth precision, device-pixel-ratio caps.
