# v5.19 — THE TANG-KI MOVES IN THE CUTSCENES TOO (and a deploy that isn't 8 minutes)

Chad, after playing:

> And why is the tangki animation always frozen in the cutscenes? He's
> supposed to have idle animation, and also magic attack animation. i
> believe he has like 4 or 5 animations that i sent and specified how to
> use them.

He is right, and "always" is exactly the word: from the FIRST frame of
every chapter-3 cutscene the tang-ki stopped dead. Measured before the fix:
**one** distinct hand position across a whole scene. After: 18 of 22 samples
in scene A, 22 of 22 in scene B.

His original spec, and what was actually true before this build:

| # | what he asked for | where | status before | now |
|---|---|---|---|---|
| 1 | **idle** at the medium event, before pressing options | ch3 | wired, and it ran in PLAY — but froze in every cutscene | fixed |
| 2 | **magic attack** on options 1, 2 and 3 | ch3 scenes A, B, C | called in all three, and never advanced past its first frame | fixed |
| 3 | **catwalk turn** for turning around / turning a corner | ch5 | done (v5.07) — `turnTo()` uses it at every real turnaround | unchanged |

| 5 | **grab torch** for the burning: note vanishes from the table as he approaches, he walks to the altar, torch take, fire crackle, no paper shown burning | ch5 scene D | done (v5.07), all five beats | unchanged |

So three of five were delivered and two were not — not because they were
never written, but because the code that plays them could not run.

## The root cause, which was not where it looked

`updateNotes(dt, t)` is chapter 3's per-frame function, and since v4.3 it
carries this, correctly:

```js
/* THE RITUAL, and a cutscene owns it outright while one is running. */
if (getState() === 'cine') return;
```

That guard exists so a scene that poses the medium is not overwritten by
the ambient wobble on the same frame. It is right. What was wrong is what
had accumulated BELOW it. Everything added since — the tang-ki's mixer
(v4.8), the encik audience's four mixers (v4.8), the two special sitters'
(v5.05) — was written underneath that line, so **a guard meant to own the
POSES was silently owning the CLOCKS.** Thirty-one animated people stopped
the instant any cutscene began.

The fix is to say which is which. The mixers move ABOVE the return; every
ambient pose write stays below it:

```js
if (medMixer) medMixer.update(dt * ...);
for (const em of encikMixers) em.update(dt * crowdLife);
for (const sm of specialMixers) sm.update(dt * crowdLife);

if (getState() === 'cine') return;      // poses only, from here down
```

The crowd still answers `crowdLife`, because a scene that drives it to 0
("everything stops at once", scenes A and B) means that and only that. The
one pose write that has to stay below is `medHead.rotation.z += ...`: `+=`
on top of what the mixer just wrote is only safe while both run on the
same frame, which is now true in play and only in play.

## The second layer, which would have bitten the moment the first was fixed

The mixer's rate was `drumBeat` — and `drumBeat` is the RITUAL's tempo,
which scenes drive to 0 to still the tent. So even with the mixer reached,
his idle would have frozen through every "everything stops" beat, and the
magic take ran at up to **3.4x** during the escalations before sticking.

`drumBeat` is the ceremony. A named take is a PERFORMANCE. They are now two
things:

```js
medRate !== null ? medRate                                  // a scene's own
  : medCur === 'idle3' ? clamp(drumBeat, 0.45, 2.4)         // the idle follows the ritual
  : 1                                                       // a take plays at its speed
```

The floor of 0.45 is the point: a man at rest still breathes. A statue was
the old behaviour and it was the bug. `stage.medRate = 0` is now the only
honest way for a scene to say "he does not move", and it is carried through
`snap`/`restore`/`reset` so a skipped scene cannot leave an override
standing.

## What this changes on screen

- Scene A's long hold — four seconds of the medium being looked at, the
  shot the scene is built around — was a photograph. He breathes now.
- Scene B's face-to-face, his head on the lens, was a statue. Same.
- The magic take reads as a spell in all three scenes instead of a blur
  and a freeze.
- The seated audience is alive through every cutscene that does not
  deliberately stop it.

## Also in this build: the deploy stops re-uploading the whole site

Chad: *"this is not sustainable"* — about an eight-minute deploy. He was
right about the cost and right to ask now. Measured: a player's download
does NOT grow with the game (sound has been split per chapter since v4.2
and models load with their chapter — boot is ~15 MB, all five chapters
~32 MB, and episode 7's assets would sit on the CDN untouched by someone
playing episode 1). What grows is the DEPLOY, because the Netlify MCP
command zips the whole directory and runs a remote build — verified by
reading the package: 25 mentions of zip, no digest handling, and no flag
to skip it. So a one-word text fix costs the same as a new chapter.

`.github/workflows/deploy.yml` is the fix. The plain Netlify CLI sends a
manifest of every file's digest and uploads only what the CDN does not
already have; on a release where the sound and models are unchanged that
is a handful of files instead of fifty. It is `workflow_dispatch` only —
no push trigger — so deploys stay as deliberate as they are today and a
work-in-progress commit can never reach the live site.

It needs one secret, set once, both steps in web UIs:
1. Netlify → avatar → User settings → Applications → Personal access
   tokens → New access token → copy.
2. GitHub → this repo → Settings → Secrets and variables → Actions → New
   repository secret → name `NETLIFY_AUTH_TOKEN` → paste.

Until that exists the workflow fails on its own check with a message
saying so, and nothing else changes: same site, same Deploys page, same
two-tap rollback.
