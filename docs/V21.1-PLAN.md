Chad, the day after v21.0 shipped: *"Find more bugs to fix in this chapter, do
it comprehensively"*. The chapter is episode 3 chapter 3,
`src/chapters/e3/e3c3.js` (v21.0, docs/V21.0-E3C3-PLAN.md). The shape is the
one that worked on episode 3 chapter 2 (v18.4, v18.5, v19.2): photograph every
beat at the phone's own ratio, read the code through several independent
lenses, have every finding checked by a skeptic BEFORE it is touched, fix, and
release with the deploy first.

This file is the build's memory. Every checkpoint is ticked here as it lands
and committed, so a lost context resumes from the last tick.

## Rules for this pass

- A finding is a LEAD until it is verified against the code as it stands
  today (quote the line) or against a photograph of the shipped build. Default
  to refuted. v12.3's sweep: about three in five unverified claims were real.
- Fix only what is verified. A fix that would change base-game feel, or any
  episode 1–2 behaviour, is put to Chad instead.
- Targeted edits on unique strings only; read the full diff before the commit.
- Deploy first (from inside `dist/`), byte-verify, then the harnesses.
