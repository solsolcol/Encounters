## 1 · THE LANE

### What he heard

`t4who` — the range officer's challenge — said:

> CEASE FIRE! Who fired? **Lane five.** What are you firing at?

and it was cued twice: once in the confusion beat in play, and once in
**scene C**, where the player has just fired three rounds himself.

### Why it was written that way, and why that stopped being good enough

The confusion beat was internally consistent. One line above the cue,
`beginConfuse` fired a scripted round —

```js
queueFn(() => { if (worldSfx) worldSfx('rifleshot', 0.75); });          // and lane five fires anyway
```

— so lane five HAD fired, and the tower was right to say so. The design
intent was a line that panics and shoots despite `k4cyc`'s "DON'T SHOOT!
DON'T SHOOT!".

From the player's seat that reading is not available. He hears a rifle he did
not fire and then the range officer challenging a lane he is not standing on,
which reads as the game addressing the wrong man. And in **scene C** it is
not a reading problem at all but a plain defect: the player fires three real
rounds through `kit.weaponShot()` and the tower blames lane five.

### The fix, and why it is better rather than only asked-for

The challenge now belongs to the **player's own first round** (`onFiredAtIt`),
and the scripted lane-five shot is gone:

```js
      sayLine('n4back');
      /* v14.3: AND THE TOWER CHALLENGES HIM. ... */
      if (shots <= 1) { queueGap(0.6); tower('t4who'); }
```

Three things follow from that one move.

1. **The line is true when it is said.** It is his round, so it is his lane.
2. **`onFiredAtIt` gains the answer it never had.** Putting a live round into
   a target area the range party has just called empty drew complete silence
   from the range, through three releases. It is the one thing a range
   officer cannot let pass, and now he does not.
3. **`k4cyc` lands better.** "DON'T SHOOT! DON'T SHOOT!" is now said to the
   only man on the range who can — instead of being immediately contradicted
   by a round nobody can be held to answer for.

Once only: `if (shots <= 1)`. Three challenges for three rounds is a machine,
not a man. It is QUEUED, so it falls in behind his own "It's coming back" and
behind whatever radio traffic is still running, and `openDecision` drops it
if the bell comes first (v12.3's rule).

What is left in the confusion beat is the three shouts and the tower's
negative — the gap the whole chapter is built on — untouched.

## 2 · THE TRIGGER KNOWS WHERE HE IS STANDING

### The engine's share — the nineteenth seam

`kit.weaponBlock(msg)`. A string forbids firing and **is what the HUD says**;
`null` allows it again. It defaults to null, so the fixture's nine weapon
promises and episode 1 — which declares no weapon at all — are untouched by
construction.

```js
function weaponFire() {
  if (!weaponDecl || state !== 'play' || !weaponWant()) return false;
  /* the chapter's own rule, before anything is spent: no round, no take,
     no flash, no raycast — and the reason on the screen */
  if (weaponBlock) { weaponBlockSay(); return false; }
```

It sits **before** the fire-gap clock as well as before the spend, so a
refused press costs nothing and is not rate-limited into silence by the
weapon's own cadence.

**The message is the chapter's, never the engine's.** What is forbidden and
why is a chapter's business, and a chapter's word goes through its own
`words`, which is where `textsync` puts it in front of Chad. The engine
hard-codes no lane.

The refusal is not only a dead press. `#nofire` — a red stencil under the
reticle, which is where the eye already is when the trigger is pulled —
carries the chapter's sentence, with `hudfail` (already in the engine's
unconditional warm set since v8.8) and a hard triple buzz. It is rate-limited
to one in 900 ms so a held trigger cannot flicker it, and its entry animation
is **restarted** on every refusal past that window, so a second, deliberate
press is visibly answered rather than silently ignored. And `body.wpnBlocked`
dims the FIRE button, so the rule is on the screen **before** it is tested —
a player who looks at the HUD never has to discover it by pressing.

A dead trigger with nothing to read is exactly the failure v12.2 spent a
release fixing ("shooting does not seem to work"). There it was a real bug;
here it is a rule; the difference has to be visible.

`weaponSetup` and `weaponTeardown` both clear it, so a chapter's fire rule is
never inherited by the next one.

**The fixture declares it and `fixturetest` proves it** (v12.0's rule — a
seam proved by the fixture first is a seam the chapter cannot hide a bug in).
Two new promises, 58 in all: a blocked press returns false with the round
count **exactly where it was** and the words on the screen, and clearing it
puts `body.wpnBlocked` and the element back.

### The chapter's share

```js
const FIRE_R = 3.0;
...
const wantBlock = (!kit || !kit.weaponBlock) ? null
  : (phase === 'line' || offLine > FIRE_R) ? DATA.words.noFire : null;
if (wantBlock !== blockNow) { blockNow = wantBlock; kit.weaponBlock(wantBlock); }
```

`noFire` is **"Shooting only allowed at lane six"** — Chad's own sentence, in
the chapter's words, on his sheet.

**DERIVED on the frame, never set by a phase** (the v11.6 law). A resume, a
replay, a reset or a cutscene that puts him somewhere else all land on the
right answer on the next frame, because there is no stored flag to leave
behind. `blockNow` exists only so the verb is called on a CHANGE — it paints
a body class and would otherwise run sixty times a second for nothing — and
`reset()` clears it with the rest of the run state (the v8.1 law, an eighth
time).

**Why 3.0 m and not `ZONE_R`.** The arrival circle is 1.35 m and the glow
drawn round it is 2.1. Arriving is a **moment** and has to be precise;
standing on your lane is a **state** the player holds through the whole of
the serials, and a rule that punishes a shuffle is a rule that reads as a
bug. 3.0 m is still well inside the 2.6 m lane pitch's neighbour, so a man
who has wandered onto someone else's lane is refused — which is the range's
own rule, and the one the chapter's whole drill is about.

**It does not replace the early-fire penalty, it complements it.** The block
is about PLACE; `onShot`'s `if (!hot)` branch (−6 sanity and `e4wait`) is
about TIME. A player standing on his lane who fires before the order is still
reprimanded and still pays.
